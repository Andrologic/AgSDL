| 5. Compare evidence | Step 4 | Stored reports agree on portable inventory/meaning, violated rules and locations, unknown extensions, phase verdicts, deferred obligations and exclusions. | 6. Document implementation evidence | Steps 3-5 | Reports identify the independent third-party implementations, source revisions, claimed units, supported and unsupported checks, unknown preservation and coverage gaps. Selected runtime declarations distinguish engine, interface, model, provider and hosting. No product integration or custom-engine implementation is required. |
| 7. Release review | Steps 1-6 | Scope-labelled conformance evidence, limitations and release notes match adopted units; repository checks pass and independent review is resolved. Tagging/publication requires its own authorization and is not performed by this plan. |

A D-only release may omit G/R implementation after explicit scope selection.
If selected, G requires sequence, true/false, input/output, approval/refusal,
timeout, terminal, cycle and missing-dependency fixtures. A negative approval
fixture routes both approved and denied to the protected invocation; G rejects
it because the approved edge must be its only incoming edge. Another negative
fixture routes an invocation's success and failure to a success terminal that
consumes that invocation's output; G rejects the unavailable-output path.
R needs unselected,
custom-unknown, known-unsatisfied and missing-evidence cases without engine
fallback. The [acceptance scenarios](../research/0.1.0-acceptance-scenarios.md)
and [evidence checklist](../research/0.1.0-implementation-checklist.md) are
preparation inputs, not evidence that these tests already ran.

The two-validator result is bounded structural evidence. It proves neither
runtime equivalence nor execution support in any third-party implementation.
Future execution conformance needs a separately reviewed general contract and
observed runs; it is not a product-integration workstream in this delivery plan.
External interface research informs comparisons without prescribing a supplier
or deriving portable requirements from one product.
