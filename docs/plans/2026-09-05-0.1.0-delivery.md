| 7. Conditional Macro execution | Maintainer selects this gate; steps 5-6 and separately authorized external work | Reviewed implementation/mapping in Macro, selected engine/interface versions and controlled inputs; observed success, failure, refusal and unavailable-capability cases for each execution claim. | 8. Release review | Steps 1-6, plus 7 if selected | Scope-labelled conformance evidence, limitations and release notes match adopted units; repository checks pass and independent review is resolved. Tagging/publication requires its own authorization and is not performed by this plan. |

A D-only release may omit G/R implementation after explicit scope selection.
If selected, G requires sequence, true/false, input/output, approval/refusal,
timeout, terminal, cycle and missing-dependency fixtures. R needs unselected,
custom-unknown, known-unsatisfied and missing-evidence cases without engine
fallback. The [acceptance scenarios](../research/0.1.0-acceptance-scenarios.md)
and [evidence checklist](../research/0.1.0-implementation-checklist.md) are
preparation inputs, not evidence that these tests already ran.

The two-validator result is bounded structural evidence. It proves neither
runtime equivalence nor actual integration in Macro. This step changes no Macro
code and supplies no running custom Macro engine. If execution is required,
completion of documentation or repository tooling cannot substitute for step 7.
