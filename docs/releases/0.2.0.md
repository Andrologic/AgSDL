# AgSDL 0.2.0 draft release notes

Status: **UNRELEASED. Candidate requirements pending maintainer adoption.**
These notes describe the proposed release scope. No 0.2 edition is published or
adopted. The candidate marker remains `agsdl-exp-flow-0.2-c1` pending final edition
allocation. The [release-status reference](../../README.md#release-status-and-history)
continues to identify 0.1.1 as published with contract `agsdl-0.1.0`.

## Proposed scope

The [candidate specification](../../spec/0.2/README.md) defines persistent Agents,
Messages with distinct instruction and information roles, optional initial
prompts, reusable content and skills, explicit configuration selection and
optional Interface constraints. Content can be inline or URI-backed, with
explicit URI origins, bounded structured results and exact scoped support claims.

Optional flow combines Agent work, Calls, deterministic Conditions, Message
preparation and explicit Joins. The candidate specifies queueing and steering,
work correlation, visible response assembly, result transfer, loops and closed
failure inputs. Non-nested local compositions preserve existing Agent identities.
Approval chains capture protected Agent or Call invocations and check freshness
at admission.

## Changes from earlier editions

The published 0.1 Document/Graph/Runtime contract and its seven reader operations
remain unchanged. The candidate uses continuing Agents and Messages rather than
repeated invocations as its interaction model. Its flow permits loops and parallel
connections beyond the frozen 0017 experiment. Neither earlier edition nor its
reports can be relabelled as this candidate.

The [migration guide](../0.2/migration.md) records manual mapping and loss review.
There is no automatic conversion. Preserve source identity, authorization,
configuration and evidence when preparing a separate candidate description.

## Evidence and limits

The [tooling guide](../../experimental/agent-flow-0.2/README.md) provides examples,
a derived schema, a static reader and checks of supplied completion, delivery
and admission records. Independent semantic comparison is pending. A schema
comparison covers shapes only; supplied-record consistency does not establish
actual attribution, delivery, authenticated authority or execution.

Composition is non-nested and serial or conditional internally. Joins use the
bounded direct-fork structure. External contracts supply Engine, Tool and Call
implementations. The candidate supplies no runtime, universal transport,
arbitrary Agent spawning, hot reconfiguration, context reset or durable restart
recovery. URI resolution grants no access, and support declarations do not verify
the referenced evidence or the consuming implementation.

Final semantic and evidence review, migration review, edition allocation and an
explicit maintainer adoption decision remain pending. Publication requires a
separate decision. Execution claims require evidence for the consuming
implementation and the behavior claimed.
