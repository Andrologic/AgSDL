# AgSDL 0.1.1 local maintenance candidate

Status: prepared locally, not published. This is
maintenance of the reference readers and repository around the existing
`agsdl-0.1.0` first-draft contract, not a new normative edition.

## Changes

- Both current reader processor Editions announce version 0.1.1 and retain
  their identities. Their autonomous modules and determined diagnostic fixes
  come from the integrated maintenance lots. Historical readers are unchanged.
- The official corpus keeps all 137 historical cases and the native empty
  System case, adding ten compact native diagnostic cases. Their expectations
  follow the normative specification; reader agreement is not an oracle.
- Distribution integrity works without Git; historical Git provenance is a
  separate check. The current comparator and readers use their own local modules.
- Four progressive examples cover seven operations through both readers,
  producing 56 checked responses. Their documents remain 0.1.0.
- A shared full verification command and GitHub Actions workflow cover repository
  checks, six reader suites, three corpus comparisons, Draft 2020-12 corpus and
  report checks, and examples. Logs and reports are retained, including failures.

The specification, feature Editions, schemas, examples and contract marker stay
0.1.0. There is no new syntax, default engine, runtime, execution interface or
product integration. A static result does not establish readiness or execution.

## Local verification and future publication

Use the [full verification procedure](../../CONTRIBUTING.md#full-local-and-ci-verification)
on the final clean candidate and retain the evidence outside the repository.
The existing regression suites cover reader imports without experimental modules
and archive checks without Git. Independent review must examine that stable SHA
and the integrated interactions before delivery is marked locally ready.

Future publication requires full verification on the integrated candidate,
recording its SHA and
manifest digest, and maintainer review of the release content. Only a later
explicit publication step may create a release tag or publish release artifacts.
No push, tag, remote workflow run, deployment or publication is part of this
local preparation.
