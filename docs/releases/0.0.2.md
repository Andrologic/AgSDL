# AgSDL 0.0.2 candidate release notes

- Status: prepared locally; not published
- Planned tag: `v0.0.2`, not created by this preparation
- Comparison base: published tag `v0.0.1`
- Release type: non-normative conceptual pre-draft

## Summary

The `0.0.2` candidate collects the conceptual and repository work completed on
`develop` after `v0.0.1`. It gives reviewers one account of the current project
state. It is not an implementable language release.

Version `0.0.1` remains the latest published version. This file describes a
candidate prepared locally for review. It does not represent an existing tag or
remote release.

## Conceptual model and conformance

[Decision 0004](../decisions/0004-approved-design-directions.md) records five
accepted directions. The proposed material now reflects those directions:

- a complete System may participate through imported Agent definitions while
  lifecycle ownership stays with the source definition owner;
- one Action occurrence may refer directly to several Authorization decisions,
  with each decision tied to its requirement and Policy application point;
- implementation features and conformance profiles replace a general ordered
  conformance-level model;
- validation phases distinguish explicitly permitted deferrals from missing,
  invalid, or unsupported information;
- the first exchange contract is bounded to reading, inspection, structural
  validation, preservation, and loss reporting.

These are accepted design directions, not an accepted language. The detailed
semantics in proposals and examples remain proposed or illustrative.

The reconciliation updates proposals 0001 through 0004 and the two conceptual
examples that originated in `v0.0.1`. Three additional non-normative examples
cover imported-Agent composition and authorization accounting, an A2A binding,
and an A2UI binding. The tag `v0.0.1` preserves the previously released forms.

## Proposals and external bindings

The candidate contains eleven proposals. Proposals 0001 through 0004 remain the
conceptual core and all retain proposed status. Proposals 0005 through 0010 add
documented binding candidates for:

- MCP 2026-07-28;
- A2A 1.0;
- Agent User Interaction Protocol, commonly referred to as AG-UI;
- A2UI;
- Agent Payments Protocol, or AP2;
- Open Agent Specification.

The repository also contains research records and non-normative examples for
reviewing these mappings. The prior-art inventory was updated, and six focused
research records document the reviewed MCP, A2A, AG-UI, A2UI, AP2, and Open
Agent Specification sources. A documented binding does not mean that AgSDL or
any other software implements it. The candidate provides no executable
interoperability evidence for these bindings.

[Proposal 0011](../../proposals/0011-first-exchange-contract.md) is the eleventh
proposal. It defines a bounded candidate contract for maintainer review. Its
scope, permitted deferral, identity interpretation, preservation rules, result
rules, representation, and executable evidence still require review or later
definition. This candidate release does not adopt it.

## Repository maintenance and verification

Decision 0003 defines the repository boundary. The cumulative work aligns the
scope, contribution guidance, governance notes, proposal index, examples,
schema guidance, and specification placeholder with that boundary. Work plans,
an implementation-readiness review, and the conceptual-reconciliation closure
record preserve the review history and its limits.

Local verification now includes:

- a Markdown local-link checker with focused tests;
- a pinned digest manifest and declaration checker for the reviewed A2A 1.0.1
  source files, with focused tests;
- an expanded `scripts/check.sh` entry point that checks required files,
  trailing whitespace, Git diff errors, shell syntax, verifier behavior, and
  local Markdown links.

These checks maintain repository integrity. They are not an AgSDL conformance
suite and do not prove the proposed semantics or external bindings.

## Limits of the candidate

Version `0.0.2` does not define or promise:

- a normative AgSDL specification or serialization syntax;
- compatibility between documents, tools, runtimes, or versions;
- an implemented parser, validator, adapter, runtime, or protocol binding;
- executable conformance or interoperability evidence;
- normative adoption of proposal 0011;
- the content, schedule, or acceptance criteria for version `0.1.0`.

Publication remains a separate maintainer action. Until that action creates the
planned `v0.0.2` tag and publishes the release, references to `0.0.2` in this
repository mean this local candidate.
