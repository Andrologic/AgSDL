# A2A 1.0 external binding example

Status: non-normative example for proposal 0005

## Intent

A document review system has two internal agents. It exposes one system
interface through an A2A 1.0 server and advertises a public Agent Card. The
example shows what the binding can relate and what remains visible only in the
complete AgSDL description.

This is a syntax-free AgSDL example. The Agent Card facts use A2A's external
model, but the example does not reproduce its JSON or Protocol Buffer encoding.

## Complete AgSDL system facts

The AgSDL description contains these definitions:

- **Document review system**, the System and lifecycle owner of its local
  definitions.
- **Intake agent**, an Agent that validates the submitted media type and extracts
  the requested review criteria.
- **Policy review agent**, an Agent that applies the review instructions and
  prepares findings.
- **Document review A2A interface**, an Interface exposed by the System.
- **Submit document review**, an inbound Interface operation contained by
  Document review A2A interface.
- **Document review flow**, a Control flow that invokes Intake agent, invokes
  Policy review agent, waits for additional input when required, and reaches
  reviewed, rejected, failed, or canceled terminals.
- **Review caller**, an external Principal class authenticated through the
  corporate identity provider.
- **Review authorization requirement**, which permits a caller to submit only
  documents in its authorized workspace.
- **Review trace requirement**, which requires input receipt, Principal
  attribution, agent invocation, state transition, artifact creation, and
  terminal outcome records without retaining document contents in the general
  log.

The internal topology permits Intake agent to call Policy review agent. Neither
agent is independently exposed outside the System.

## Binding requirement and resolved assertions

The A2A external agent binding requirement attaches to Document review A2A
interface. It declares the required protocol version, capabilities, security
mapping, fallbacks, and portable mapping constraints. A separate A2A resolved
external agent binding satisfies that requirement for this deployment and
records the exact card, interface, and mapping assertions below.

1. `exposes boundary as` relates Document review A2A interface, at Document
   review system's external boundary, to this exact public Agent Card
   observation.
2. `binds interface through` requires a compatible A2A AgentInterface. The A2A
   resolved external agent binding selects the advertised HTTP+JSON entry. Its
   endpoint and protocol version remain resolved binding facts rather than
   portable properties of Document review A2A interface or Submit document
   review.
3. `advertises as service` relates Submit document review to the AgentSkill
   `document-policy-review`. The assertion matches input and output media types.
   It does not equate the AgentSkill with either internal AgSDL Skill or either
   internal Agent.
4. `observes occurrence as` relates each scoped A2A Task to one execution of
   Document review flow. The relation includes server identity, selected
   interface, Task ID, context ID, and protocol version.
5. `seals as` relates a completely assembled A2A review Artifact to an AgSDL
   immutable artifact after a content digest is recorded.
6. The Task occurrence mapping declares these intended state correspondences:
   `TASK_STATE_COMPLETED` to reviewed, `TASK_STATE_REJECTED` to rejected,
   `TASK_STATE_FAILED` to failed, and `TASK_STATE_CANCELED` to canceled.
   `TASK_STATE_INPUT_REQUIRED` and `TASK_STATE_AUTH_REQUIRED` map to waits, not
   terminals. No correspondence has runtime evidence in this example.

For this binding requirement, `TASK_STATE_AUTH_REQUIRED` explicitly selects A2A
section 7.6's in-task authorization procedure. It does not reinterpret the state
as an initial OpenID Connect authentication challenge.

The binding requirement requires streaming and corporate OpenID Connect. Push
notification support is optional because polling is the declared fallback. The
citation extension is optional and has a portable fallback: the review result
remains a plain finding list without citation metadata.

## Runtime path

1. The caller resolves the public Agent Card and selects its preferred
   HTTP+JSON interface. The resolver records an Agent Card observation instead
   of replacing the prior snapshot. It then creates an A2A resolved external
   agent binding that identifies the satisfied requirement, resolved card
   reference, selected observation, exact interface entry, endpoint, protocol
   version, tenant, and target runtime.
2. The caller authenticates with corporate OpenID Connect. The server maps the
   authenticated subject to Review caller and evaluates Review authorization
   requirement. The Agent Card scheme declaration does not supply that
   authorization decision.
3. The caller sends an A2A Message containing a PDF part. The binding records
   the A2A Message as the inbound Message occurrence for Submit document review.
   `ROLE_USER` identifies the A2A side; the separate authentication evidence
   identifies the Principal.
4. The server returns an A2A Task in `TASK_STATE_SUBMITTED`. The Task occurrence
   correlates with one Document review flow execution. It is not the Control
   flow definition.
5. Intake agent determines that a review region is missing. The server emits
   `TASK_STATE_INPUT_REQUIRED`. The state is interrupted, not terminal. The A2A
   1.0.1 HTTP+JSON sections disagree on whether the stream closes here, so the
   binding records the observed behavior rather than assuming either outcome.
   The caller sends another Message scoped to the same Task.
6. If the earlier stream closed, the caller subscribes again or polls. A new
   subscription begins with the current Task. The server then emits
   `TASK_STATE_WORKING` and Artifact updates. The adapter assembles updates with
   the same Artifact ID. It does not create an immutable artifact on the first
   chunk.
7. The final Artifact chunk arrives, followed by
   `TASK_STATE_COMPLETED`. The adapter verifies assembly completeness, computes
   a content digest, and creates the immutable review artifact record. A future
   conforming adapter may let the AgSDL flow reach reviewed because the mapping
   assertion explicitly maps this A2A state, but only after a runtime test
   covers that transition. This example supplies no such test evidence.
8. The stream closes. The trace records delivery and processing separately.
   Task history is not used as proof that every Message was retained.

## Alternate outcomes

- `TASK_STATE_REJECTED` maps to the flow's rejected terminal only under the
  explicit state mapping. The A2A state alone does not say whether policy,
  unsupported content, or server discretion caused the refusal.
- `TASK_STATE_FAILED` maps to failed. Partial Artifact updates remain execution
  data unless a separate partial-output rule seals them.
- `TASK_STATE_CANCELED` maps to canceled. The mapping does not claim that prior
  effects were rolled back.
- `TASK_STATE_AUTH_REQUIRED` creates an authorization wait. The caller follows
  the declared out-of-band credential path. No credential is placed in the A2A
  Message.

The example therefore illustrates intended semantics and makes no
interoperability claim.

## Counterexamples

- A processor imports the public Agent Card as an AgSDL Agent and invents its
  internal tools and control flow. The card describes only an opaque external
  boundary.
- A processor turns `document-policy-review` into an AgSDL Skill because the
  names look compatible. The A2A item is advertised service metadata and has no
  skill-addressed invocation operation.
- A processor treats `TASK_STATE_INPUT_REQUIRED` as terminal because blocking
  SendMessage returned. The state is interrupted and accepts continued work.
- A processor seals the first Artifact update as immutable, then mutates it when
  another chunk arrives. Assembly must finish before sealing.
- A processor treats the OpenID Connect declaration as permission to review any
  document. Authentication and authorization remain separate.
- A producer claims the HTTP+JSON and gRPC interfaces are equivalent because
  both appear in the card. That claim needs runtime evidence for both bindings.
